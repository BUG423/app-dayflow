# 简化填写、今日休息与冲突替换契约

日期：2026-10-31。本轮承接四步向导，优先减少普通用户需要理解的设置；SIMPLE/REST 要求覆盖上一轮契约中的 EXC-01 可见入口设计，OVR 要求以选择后明确确认替换，取代上轮对其他计划占用分钟一律禁选的做法。已有计划格式和历史数据继续兼容，代码、Node 测试、微信模拟器、云端及真机分别验收。

## 需求与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| SIMPLE-01 | 保留四步，减少每页概念 | 使用“做什么 → 选时间 → 重复 → 确认”，普通用户只需填写事项、日期和时间、重复方式，再确认。每步保留已填摘要，返回不丢内容；分类、期限、动作等补充放在默认收起的“更多设置”，不要求理解内部时间块或技术标识。 |
| SIMPLE-02 | 重复设置用日常语言 | 提供不重复、每天、周一至周五、每周指定几天；仅选择指定几天时展示星期选项。确认页用自然语言描述实际重复范围，时间可用性和最终版本/冲突校验继续生效。 |
| SIMPLE-03 | 普通计划不承担请假操作 | 移除普通向导中的“特殊安排”“某天不执行”“仅修改某天”操作。已有 `Schedule.exceptions`、多时段、任务、动作和来源保持原值，不因界面精简删除或压平。导入格式继续兼容日期例外，但不把它作为新建的必填概念。 |
| OVR-01 | 一个确认替换重复冲突 | 主时间默认允许选择其他计划已占用的分钟，不增加覆盖模式开关；同组其他时段仍不可选。时间选择或重复范围稳定改变后，展示新计划实际范围内的全部冲突并通过原生确认一次处理，不必逐日删除。选择时间、查看提示或暂时确认替换均不持久化，最终保存前原计划不变。 |
| OVR-02 | 说明完整旧块边界 | 覆盖删除的是与新计划重叠的完整旧 `TimeBlock`，不把旧任务、训练动作截短，也不删除同组无冲突时段。确认前列出旧安排名称、完整起止时间及受影响星期/生效日期；旧块超出新时段的部分也一并移除，必须明确说明这一点。 |
| OVR-03 | 精确保留未受影响日期 | 新计划范围外的旧期限、星期、跳过日期及替换日期继续按原计划执行。只修改未来可变日期，已锁快照、已有记录与历史来源保持。复杂重复通过兼容的规则片段和有限例外表达，不扩展模板 schema，不用任意七天窗口当作全范围证明。 |
| OVR-04 | 最终确认与失败保护 | 覆盖预览只生成草稿，最终保存按一次版本租约提交一个新版本。取消、版本变化、校验失败或写入失败均不改原有效计划/版本/快照；修改任何会影响覆盖范围的草稿内容后重新预览和确认。正常新建不会自动覆盖。 |
| QA-OVR-01 | 覆盖重复而不伤历史 | 验证每天08:00–12:00一次替换旧各星期09:00–12:00；只覆盖部分星期/有界期限；旧skip/replace与新例外；完整旧块和兄弟保留；锁定日期、活跃计时引用、取消、过期版本和写入失败。 |
| REST-01 | 今日统一入口 | 在今日页提供“今天休息”。理由可选、最多200字。确认前说明正在进行的任务会停止、已完成记录保留；休息成功后显示状态、理由及“恢复今天安排”。查看其他日期不能误操作成那一天休息。 |
| REST-02 | 整天暂停，不伪造执行 | 休息是当地日期的独立覆盖层，所有当日安排暂停；不删除原计划、不改模板和日快照，不把待办批量标为完成或跳过。只给今天原本为 `doing` 的记录追加真实用户停止产生的 `aborted` 事件；完成、延期、跳过和其他原记录保持。 |
| REST-03 | 执行和计时一致 | 休息中阻止当天开始、继续、勾选完成等执行写入和新计时/继续计时，其他日期保持原语义。暂停属于今天的独立倒计时；停止进行中记录使实际用时在确认时结束，不继续累计休息时长。恢复只解除休息限制，不自动重启任务或倒计时。 |
| REST-04 | 日期、恢复和提醒明确 | 休息只作用设备本地今天，次日正常执行；过去的休息文字可作为本机状态展示。休息时停止今天的前台任务提醒，恢复后不自动补发一批过时提醒；不能承诺已登记的微信后台订阅消息已撤回。 |
| REST-05 | 严格读取和失败保护 | 理由、日期和存储严格校验；损坏数据不能当空白覆盖。休息状态、今天记录和计时写入失败时恢复原存在性和值，不返回伪成功；重复点击不能重复停止或反复追加事件。取消/恢复也只修改今天的休息状态。 |
| REST-06 | 统计和隐私如实 | 休息不是完成，不改完成率分子或分母，不消除未完成事实或伪造连续执行。理由属于用户本机输入，不写入公共示例、日志或仓库；本轮不扩展云同步 payload。 |
| QA-REST-01 | 有实际证据 | 纯服务回归覆盖跨日隔离、已完成保留、进行中停止、倒计时暂停、恢复不重启、损坏/写入失败及幂等；页面测试覆盖入口、理由、休息/恢复、前台提醒和精简填写。真实模拟器需独立编译、点击和存储精确恢复证据。 |

## 模型和接口

保留现有五个业务概念、`PlanTemplate`、`DailyInstance` 与 `ExecutionRecord` 的格式。新增本机 `dayflow.restDays.v1`，由休息服务独占；它表示暂停当天安排的用户选择，不是新的周期规则，不写入 `Schedule.exceptions`。

```ts
interface RestDay {
  date: string;       // 设备当地 YYYY-MM-DD
  reason: string;     // 可空，最多200字
  startedAt: number;
  updatedAt: number;
  active: boolean;
  resumedAt?: number;
}
getDayRest(date: string): RestDay | undefined;
isRestingToday(): boolean;
startRestToday(reason?: string): RestDay;
resumeToday(): RestDay | undefined;
```

`getDayRest` 是严格只读查询，不能创建日快照或执行记录。`startRestToday` 只允许操作当前本地日期，读齐并验证原数据后，协调今天进行中记录、倒计时和休息状态；相关写入发生失败时回滚。理由去掉首尾空白后保存，重复确认保持幂等。`resumeToday` 不回滚已经发生的真实停止事件，不将原中止记录自动改回进行中。

服务层统一执行门禁，页面禁用按钮只是提示，不能由旧训练详情路由或直接事件绕过。休息存储的只读校验与协调逻辑分开，避免 `records`、`timer` 和休息协调器形成循环依赖。统计继续消费原快照和真实执行记录；不能为显示“休息”改写统计事实。

## 冲突替换边界

主时间选择保持直接：其他计划的占用仍列名称与起止，用户可以直接选新时段；发生冲突后用一次确认说明将替换哪些完整旧块，不要求先理解或开启覆盖模式。同一安排内部的兄弟时段继续限制选择，不能借覆盖悄悄删除当前组的其他块。

替换按新草稿实际发生日期判断，不根据两个规则存在相同星期就删除整条旧规则。例如：每天08:00–12:00的新工作安排从11月2日生效，将在未来符合条件的日期替换旧09:00–12:00工作块；旧规则中的下午工作、晚间训练及新计划生效前的日期仍保留。若新规则只每周一执行或只执行两周，旧安排在其他星期和两周之后继续执行。

新草稿的跳过日期不能造成旧安排被误删；新草稿或旧规则的单日替换内容按该日期真实时段判断。旧规则即使包含多个时段，也只删除发生时间冲突的完整块。旧块为09:00–13:00，而新块为08:00–12:00时，确认中必须说明旧09:00–13:00整段将被替换，不能让用户以为还会保留12:00–13:00。

纯替换引擎生成候选模板与受影响明细，页面只负责展示和确认，服务负责只读日期锁、标识兼容、完整周期分析及提交前复查。覆盖不会清空已锁日快照，也不更改旧记录、照片、延期来源或未受影响的块标识。尚未结束的计时目标若会被删除且没有保留快照，继续沿用原有引用保护，要求先处理该计时，不遗留孤立计时目标。

纯引擎入口是 `prepareScheduleOverwrite(template, draft, options)`，返回候选 `template`、准备后的 `schedule` 和完整旧块 `removed` 明细。服务的 `previewScheduleOverwrite(input, expectedVersion?)` 额外提供 `lease`；页面确认后只在最终保存调用 `saveScheduleOverwrite(schedule, expectedVersion, confirmedLease)`。服务重新计算预览并比较租约，版本或影响集合变化即要求重新确认。写入失败恢复 `plans`、`planVersions`、`instances` 三个拥有的 key 的原值与存在性，不触碰其他应用数据。

覆盖预览展示规则范围和完整旧时段，而不是仅列一个代表性日期冒充全部影响。任何可能改变覆盖集合的时间、日期、重复、期限或内容修改后，须重新计算覆盖明细；预览时的许可不能用于后来不同的草稿。最终保存只产生一个模板版本，不用先删除旧规则再保存新规则的两次用户提交。

## 界面文案

确认文案使用“今天剩下的安排将暂停。正在进行的任务会停止，已完成记录保留。明天照常。”理由提示使用“可选，例如临时有事或想休息一下”，不要求填写健康或其他敏感信息。

休息页仍允许查看原时间轴和已完成内容，未执行事项用“今天休息”解释；恢复按钮说明“恢复后可自行继续，任务和计时不会自动开始”。理由过长、保存失败或损坏数据用明确中文反馈，保持原状态。

## 数据同步与验证边界

本轮休息状态和理由只保存在本机。现有云同步使用固定白名单，不能把新增 key 偷带进旧 payload；云端恢复或更换设备不会同步这份休息状态，界面不能声称已同步。休息操作也不代表服务端已取消此前登记的订阅消息，本轮不调用云权限或发布接口。

测试只用合成理由、计划、执行记录和倒计时。验收脚本备份并恢复全部 `dayflow.*` 的值与存在性，包含新 key；截图、原始记录、完整控制台和本机 AppID 不提交。最新执行结果记录在 [简化计划与今日休息验证报告](SIMPLE_PLANNING_REST_VALIDATION.md)，不沿用上一轮207项或更早模拟器通过数量。
