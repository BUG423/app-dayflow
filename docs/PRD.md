# 日程流产品需求 V0.2

## 定位
日程为底座，执行与习惯养成为核心，训练只是一个可扩展的任务类别。

## 业务名词
- TimeBlock: 固定占用 fixed、并行待办 parallel、顺序执行 sequence。
- Task: 时间块内可独立执行的事项，可含零个或多个 Action。
- Action: Task 内部执行步骤；有步骤的 Task 以 Action 作为完成率的叶子单位，不重复计算父 Task。
- Schedule: 以星期几、当地钟点和日期例外描述的周期规则；PlanTemplate 保存规则集合及版本。
- DailyInstance: 某一天生效的计划快照；执行后或过去日期锁定，历史统计读取该快照。
- Record: 某日某任务的完成状态和用户输入，永不因为模板改动被覆盖。

## 功能范围
M1: 七日导航、日期定位、时间轴、并行折叠、顺序动作、任务勾选、昨日复盘、本地统计。
M2: 任务状态细化（跳过/延期/停止）、日期切换中的提醒和恢复。
M3: 可视化编辑、导入校验、云端用户隔离、照片打卡、版本化计划。
M4: 历史和连续执行统计、15 分钟简化方案、用户自主选择的阶段目标与参考规则。
M5: 微信订阅提醒可行性、外链与视频合规、安卓 iOS 真机兼容与上线。

## 关键验收
1. 任何日期默认显示所在周周一至周日；今天默认选中。
2. 固定占用仅展示，不参与完成率计算。
3. 并行任务独立勾选；顺序训练每个动作独立勾选。
4. 相同星期不同自然日期的完成状态互不干扰。
5. 用户更改模板不能更改已有历史记录；修改前先固化旧记录对应的编辑前计划快照。
6. 本地日期转换不能受 UTC 日期边界影响。
7. 今天首次进入读取昨天的记录，且每天最多弹一次；无昨日数据不弹。
8. 危险信号与中止应始终可用；演示运动数据不构成医疗建议。

## 公开数据约束
禁止将用户个人病历、医疗术后详情、私人照片与访谈信息写入公开仓库。

完整状态和时钟推算必须区分：“当前时间落在计划区间”只是日程提示，不能自动把任务写成进行中或完成。只有用户操作产生执行记录。直接完成没有开始事件时，不伪造开始时间。

延期先保留原日记录。用户在计划页一键确认后，在目标日空档创建有来源关联的例外任务；已执行/锁定的目标日不能被覆盖。应急切换同样不能替换已有执行记录的日实例。界面应明确这些限制并允许选择其他日期。

## 外部条件与发布门槛

代码实现、本地单元测试、微信模拟器、真实云环境及 Android/iOS 真机是不同验证层次。照片选择与授权、云数据库/文件权限、订阅模板和后台送达必须有真实环境证据；没有配置时界面如实提示不可用。

首次云同步须用户主动开启；上传、恢复或冲突选择都需清楚表达结果，不自动覆盖另一端。公开仓库不包含本机 AppID、凭证、照片、执行记录或云环境私密配置。没有实际日志不能标记真机兼容或正式发布完成。
