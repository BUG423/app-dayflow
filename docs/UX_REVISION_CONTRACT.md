## 需求与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| UX-STAT | 修复统计页挤压 | 周导航、日期范围、历史卡片在 390px 和 320px 模拟器无横向溢出或逐字竖排；按钮尺寸不受原生默认宽度撑大；长日期/标题可换行；主要操作触区至少 44px。 |
| UX-DATE | 精简今日日期导航 | 移除七日栏上方的日期标题及左右箭头；点击七日日期仍可选日；在日期区域左右滑动可到前后日期范围；保留回到今天入口；垂直滚动和轻触不误切日期，跨月/跨年仍用本地日期。 |
| UX-PLAN | 直观添加安排 | 默认聚焦一个普通安排的名称、时间和重复日期；固定占用与可打卡事项用中文表达；多时间块、例外、生效范围、动作细节等收进明确的高级入口。简化输入后仍通过原计划验证器保存，编辑原有复杂计划不丢字段。 |
| UX-PLAN-LOCK | 保存结果可理解、可看见 | 新建单次安排不默认落入已锁定今天；最多向后查看七天选择首个可编辑日期并说明原因。手选锁定日保存必须拒绝并保留草稿；重复规则若今天已锁定，明确说明只影响之后符合规则的未执行日期，不能显示暗示今天已修改的成功反馈。 |
| UX-ME | 精简我的设置 | 首屏以提醒、训练偏好、数据管理等清晰入口组织；去除版本/内部存储说明占据的顶部卡片；复杂规则、后台提醒列表和同步说明按需展开，功能与失败提示不丢失。 |
| UX-COLOR | 克制且有层次的配色 | 白色内容面、浅灰背景、深色文字；蓝色用于主要行动和选择；任务类别可用少量辅助色，成功/提醒/异常分别使用一致的语义色。不能再让普通卡片统一铺浅绿色；状态必须同时有文字，不能只靠颜色。 |
| SCH-OVERTIME | 明确普通加班安排 | 加班作为 `fixed` 工作占用，与其他安排相同地展示和编辑，不做特殊事件系统，不计任务完成率。以当前示例运动 18:30 结束至 23:00 睡觉之间空档补充可编辑示例；不推断通勤/晚餐时长，不覆盖用户修改过的模板或已锁定日快照。 |
| CLOUD-GUIDE | 说明如何支持云服务 | 区分“测试号限制”与代码缺失；给出正式小程序 AppID、开发者身份、关联云环境和部署验收步骤；用户自行完成登录、协议及计费选择。本轮不自动开通、部署或改变敏感权限。 |

用户已说明加班与工作/训练一样是普通日程，并提出二四六游泳及一三五训练后到睡觉前有空余时间。因此本轮示例范围为周一至周六，周日不自动加入。18:30–23:00 来自当前示例时间边界，不表示已确认真实游泳返程时间或每晚工时。用户仍可调整起止、重复星期或删除。若已有自定义模板，补充安排必须经明确操作保存，不能在页面打开时静默重写。

## 模型和接口

- 保持 TimeBlock、Task、Action、Record、Schedule，以及 PlanTemplate/DailyInstance 结构不变。没有新增云数据 schema 的必要。
- 今日手势只改变被选择的本地日期/日期窗口，不产生执行记录；固定加班没有 Task/Action 执行目标。
- 计划页简化字段只是输入方式；仍通过 `saveSchedule` / `saveTemplate` 等既有服务完成校验、版本比较和旧历史固化。
- `getDateEditState(date)` 是只读锁检查接口，返回 `{ locked, reason }`，其中原因为 `past`、`recorded`、`snapshot` 或空值。它不能调用会创建日实例的接口，不能生成快照或写存储；损坏数据须抛出错误，不能当作未锁定。现代 v2 记录存在时保持其权威性。
- 新建单次安排如发现今天不可编辑，从明天起最多检查七个自然日；默认改用首个可编辑日期时必须在表单说明，不以隐式改日替代提示。七天内没有可编辑日或读取失败时保留草稿并说明，不能继续保存到锁日或假报成功。用户主动选择锁定日期后，保存前再次检查并拒绝；不能解锁、追加到历史快照或写入不可见的仅当天规则。
- 周期安排允许保留周期规则，但今天若锁定，保存反馈必须说明今天保留原安排，仅之后符合重复规则的可编辑日期生效；原快照及执行事实不变。提交前锁状态可能变化，须重新检查，不能只依赖打开表单时的结果。
- 编辑既有复杂规则时，收起的字段及未编辑时间块保持原值。切换基础/高级视图本身不保存、不清空、不改任务标识。
- 我的设置按需展开仅改变页面状态；提醒、阶段、同步及冲突处理沿用服务接口。订阅仍必须在用户直接确认手势内调用原生授权，不能因折叠而改成自动授权。
- 现有执行事实、照片与账户隔离规则不因换色、导航或表单调整而迁移或删除。

内置示例使用新版本区分加班补充；已有保存模板保持原值。旧版本缺失的历史快照仍依据旧示例还原，不能用新版多出的固定安排假称过去原本已排。未执行未来派生快照可按模板版本刷新；锁定、过去和已有执行事实的日期按历史隔离约定保留。

计划页默认新建单次安排，基础字段是名称、起止时间、所选日期/重复方式和是否需要完成打卡。已有复杂安排自动展示高级编辑；计划工具中的示例先提供只读文字预览，经用户明确确认后才能替换未来模板。隐藏或展开高级/导入/版本/训练周览不自动保存。

UX-PLAN-LOCK 是本轮集成后发现的补充验收项，须对最终修改另做纯逻辑/页面合同和真实模拟器验证。此前正在运行或已经结束的模拟器记录不能直接作为该修正的通过证据，最新范围以 `UX_VALIDATION.md` 为准。

## 配色研究依据

这些来源用于理解成熟设计体系，不代表做过“最主流产品”排名，也不引入这些组件库作为运行时框架。

- [腾讯 TDesign 色彩](https://tdesign.tencent.com/design/color) 与[官方语义色定义](https://github.com/Tencent/tdesign-common/blob/develop/style/web/theme/_light.less)：品牌、成功、提醒、错误等颜色职责分离。
- [Ant Design 色彩](https://ant.design/docs/spec/colors-cn/)：中性色负责大部分文字、背景和边界；品牌色用于关键行动与高亮；功能色保持用户认知一致。
- [WeUI](https://weui.io/)：微信场景下的基础交互参考，不照搬页面或把微信绿铺满所有内容。

本项目选择蓝色行动点与中性内容面，是针对当前信息密度的设计决定；运动、工作、兴趣等辅助色只承担识别，不替代中文名称。

## 云服务接入边界

当前本机测试号的云查询返回 `-601059`，不能使用云服务；这不是把一个界面开关打开就能解决的问题。环境数量仍未知。

更换真实 AppID 前先保留私有本机备份。不同 AppID 的缓存与文件沙箱可能不同，现有“复制当前模板”仅导出计划，不包含执行记录或照片文件，不能作为完整数据备份。切换后旧数据迁移须单独设计并验收，不能承诺会自动带入；本轮没有修改 AppID。

1. 在微信公众平台注册正式小程序，取得该小程序 AppID；开发者工具的登录微信应有该小程序的开发权限。AppID 只配置本机，不提交本机配置或任何密钥。
2. 通过微信开发者工具的云开发入口，使用对应微信公众平台账号进入，核对小程序与腾讯云账号的绑定关系。已有腾讯云环境不一定已关联该小程序。
3. 由用户完成必要身份确认、服务协议、权限授权、环境和计费选择；不假设永久免费，不代替用户确认。
4. 云环境可查询且归属正确后，再按 `cloudfunctions/README.md` 的清单配置环境标识，部署同步/提醒函数和最小权限规则；默认拒绝设置不能只为演示而放开。
5. 使用至少两个测试账户验收数据库与文件隔离、同步冲突、照片权限；另验收订阅模板、单次授权、受控定时入口及发送结果。发送接口受理不等于用户已收到。
