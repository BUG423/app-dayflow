## 可重复执行

`npm run test:wechat` 已转发到全 key 验证入口。普通本机 PowerShell 必须继承有效 USERPROFILE、LOCALAPPDATA、PATH、PATHEXT；受限沙箱不用于微信业务 CLI。

```powershell
pwsh -NoProfile -File .\scripts\wechat-iteration.ps1 -Mode Environment
pwsh -NoProfile -File .\scripts\wechat-iteration.ps1 -Mode Validate
```

pending 不重放原写入。先按原目录查询终态，再恢复：

```powershell
pwsh -NoProfile -File .\scripts\wechat-iteration.ps1 -Mode Poll -RunDirectory '<实际目录>'
pwsh -NoProfile -File .\scripts\wechat-iteration.ps1 -Mode Restore -RunDirectory '<实际目录>'
```

任何恢复失败都保留 `restoreNeeded: true`，并阻止下一轮。不要删除备份或清空微信存储来代替恢复。

独立照片诊断入口为 `scripts/wechat-photo-diagnostic.ps1`。只读布局取证入口为 `scripts/wechat-visual.ps1 -Label default|narrow`，要求界面已回真实今天，不修改业务数据；设备下拉切换需在核心回归结束后进行。加 `-VerifyNavigation` 时会全 key 备份、重编译今日、执行日期导航点击并在最后双重恢复；该流程不是只读。

```powershell
pwsh -NoProfile -File .\scripts\wechat-visual.ps1 -Label default -VerifyNavigation
pwsh -NoProfile -File .\scripts\wechat-visual.ps1 -Label narrow -VerifyNavigation
pwsh -NoProfile -File .\scripts\wechat-visual.ps1 -RestoreRunDirectory '<实际布局验收目录>'
```

布局流程遇 pending 时同样先用 iteration 的 Poll 查询原目录终态，再用上面的布局恢复入口，不重放写入。

完整控制台收集使用 `scripts/wechat-console.ps1`，通过官方 `grep -n .` 读取全部行并保留在本机 ignored 目录。`grep -i error` 空结果只说明该模式没有匹配，不能证明控制台为空，也不代表开发工具本身没有错误/警告。最终需与桌面调试器的实际错误来源对照。
