# Dayflow 架构约定

## 结构
1. Pages：小程序 UI 与事件处理（不直接写静态训练数据）。
2. Data：只读示例周模板，按星期数返回 TimeBlock。
3. Utils：纯日期、当前时间块、完成率逻辑，可在 Node 下单元测试。
4. Services：本地计划、快照、执行事实、偏好、媒体和可选云同步。页面经服务接口操作，不直接拼接云端用户标识或读取私密配置。

## 当前体验修订的约束

[中文体验修订契约](UX_REVISION_CONTRACT.md) 定义统计布局、日期手势、简化计划输入、我的设置、语义配色和普通加班补充。此次不变更五概念模型或云数据 schema；页面输入简化不意味着删除业务能力。

- 日期手势只在日期区域识别明确横向操作，不抢占页面垂直滚动；轻触继续走日期点选。切换日期不写 Record，跨月跨年使用已有本地日期工具。
- 表单基础/高级展开状态属于页面状态；原规则中未编辑的任务标识、时间块、例外与可选动作字段必须原样保留，保存仍经既有验证与历史固化流程。
- 计划页通过只读 `getDateEditState(date)` 区分过去、已执行或快照锁定日期；检查不创建实例、不写存储，数据损坏拒绝操作。单次新增选择可编辑日，保存前再次检查；周期安排说明锁定今天仍保留旧内容。禁止为让新安排可见而解锁或追加历史快照，也禁止保存不可见单日规则后泛称成功。
- 我的设置的按需展开不能改变订阅授权时序，也不能自动开启云同步。阶段、提醒、冲突和失败提示仍由原服务负责。
- 普通加班复用 fixed 工作占用，没有执行叶子目标；新增示例不能回填已锁定历史，也不能在页面加载时静默改写用户自定义模板。
- 主题区分行动色、类别色、状态色与中性色。类别和状态始终保留文字，颜色不参与业务判断；原生按钮需明确约束尺寸并验证窄屏，不能仅凭 WXSS 声称布局通过。
- 云服务开通是账户、环境与权限部署工作。本轮文档说明路径，不修改本机 AppID/云环境，不自动接受服务协议、授权或计费选择。

## 核心约定
- 日期键：YYYY-MM-DD（设备本地）。
- 周一为一周开始；JS getDay(): 0 代表星期日。
- 开始时间包含、结束时间不包含，即 [start,end)。
- 并行事项：一个时间块内有多个 Task，每个 Task 可独立执行；同一时间段可以重复。
- 顺序训练：任务内含带开始和结束时刻的 Action；页面 actions 列表只是叶子执行目标的投影。
- 用户操作只更新对应日期和 targetId 的执行事实并追加事件；不把时间进度当完成进度。
- fixed 类型不计入完成率分子或分母。
- 空状态：完成率显示 0 / 0，不认为自动完成 100%。

## 五概念与历史边界

本轮的共享模型、精确字段与签名冻结于 [迭代契约](ITERATION_CONTRACT.md)：TimeBlock 描述容纳方式，Task 描述事项，Action 描述任务内部步骤，Record 保存真实状态和事件，Schedule 描述本地周期与例外；DailyInstance 保存生效模板版本及快照。

有 Action 的 Task 以 Action 计完成率，无 Action 的 Task 以自身计完成率，不双计父子。固定占用没有执行目标。既有 `PlanBlock.actions` 是叶子单元的 UI 投影，不能再把此兼容结构当成完整模型。

已锁定实例不随模板编辑重建。过去日期和第一次执行使实例锁定；未执行的今天/未来允许用新模板重建。第一次编辑前必须为旧记录日期固化编辑前模板，不能等新模板保存后再回推旧历史。

## 安全
本地数据是离线可用的主路径，云同步默认关闭。服务端从可信微信上下文取得用户标识；客户端提供 owner 不能作为授权依据。同步使用版本比较，冲突保留两份；本地文件路径不进入跨设备 payload。用户主动选择照片与开启同步后才允许上传，真实数据库/存储规则仍须部署后验证。

提醒设置与前台提示不等于后台推送。用户开启后，前台时钟按日期/块/起始分钟去重提示，页面隐藏即停止；订阅消息受模板、授权与微信平台能力限制。阶段仅为用户自选目标和参考规则，实际动作强度变化经计划编辑确认，不作医学安全推断。

照片入口在平台隐私授权接口可用时先等待授权，再进入原生选择器；拒绝或取消不产生照片记录。一次性订阅请求必须由用户直接点击确认按钮触发，先展示具体提醒再请求该模板授权，授权成功才登记；云能力预载在确认前完成，确认点击处理器须在首次异步等待之前调用原生授权。受控测试可验证回调顺序与失败保护，不能证明原生授权界面或微信额度已经真实可用。

未关联照片保存副本的自动回收尚未实现，当前移除只删除关联元数据。实际云存储规则、订阅模板/定时调用权限、后台隐私申报和真机兼容属于独立的部署或发布验收，不能由本地规则文件、ready 标记或模拟器结果代替。

## M1 验证与页面生命周期

- 今日页仅在前台运行时钟，每秒检查本地日期/分钟，仅在分钟变化时刷新页面；返回前台立即刷新，隐藏和卸载时清理时钟。
- 跨午夜只让原先查看今天的页面跟随新日期，保留用户主动选择的其他日期。
- 模板和训练路由统一通过 `parseLocalDate` 校验日历日期，避免 JavaScript 日期自动进位。
- 显示层读取失败可降级为空视图；写入前必须独立成功读取有效记录。读取失败或数据损坏不能被当作空存储再写回，写入失败不能返回伪完成状态。
- `tests/helpers/miniprogram.js` 转译实际 TypeScript 模块，在隔离 VM 中提供微信 API、存储和可控时钟。它验证逻辑与生命周期，不验证微信编译器、WXML、原生组件或真实持久化介质。
- `scripts/wechat-smoke.ps1` 使用开发者工具自带的新版 `wechatide` 接口，无新增应用运行时依赖。模拟器证据与 Node 测试分开记录。
- 自动化日志将原生 stderr 诊断与 stdout JSON 分开处理；路由跳转后重新确认当前页面栈再绑定选择器。重编译期间只允许有界重查已知的只读桥接超时，不能自动重放点击、写入或授权。上述行为已有契约回归及真实模拟器运行证据。

## 模块依赖与失败保护

- domain 只含公共类型；默认模板及日期/完成率工具不依赖页面。
- plans 管计划、版本和日快照；records 在写执行事实前调用 plans.lockDailyInstance。plans 迁移时直接严格读取约定的记录 envelope，不导入 records 服务，避免循环依赖。
- insights 可依赖 plans 与 records，但不被二者反向依赖；media、preferences 独立拥有各自的存储 key。
- 一次性后台 reminders 使用 plans/preferences 生成明确候选，并通过 sync 的可信身份入口绑定当前账户；它与前台提示去重、倒计时独立。服务端定时执行以原子领取和单次发送保护，未知结果不自动重试，不自行扩张周期授权。
- sync 使用严格导出/恢复接口和固定 key 白名单，不能调用显示层吞错后返回的空视图上传。远端恢复先验证完整 payload，跨 key 写入失败保留备份并回滚已写入部分。
- 云函数共享日期、计划、记录、偏好、日实例和照片的纯验证构建产物，使用 `npm run build:cloud-validation` 生成。测试只在内存重建并比较已提交产物，避免服务端接受客户端拒绝的快照或照片，也避免测试自动改写掩盖过期产物。身份、云环境、文件归属和版本事务仍由服务端独立验证。
- 模板保存顺序为历史快照、旧版本、当前模板；失败可保留安全的冗余快照/版本，不能覆盖原有效模板或执行记录。旧 v1 保留，v2 一旦存在便不重复合并旧数据。
- 延期标记与目标日安排是两个用户动作。目标日生成稳定 ID 的单日例外并保存来源关联，不改写原日历史，也不能覆盖已锁定目标。

具体存储 key、负责文件与所有权见迭代契约。模块作者补纯逻辑测试，QA 在集成后补模拟器路径；技术负责人负责集成和验收，不直接实现各模块业务代码。
