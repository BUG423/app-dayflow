# 分步计划与可用时段契约

日期：2026-10-31。基线提交：`e60eb538fce308d19a58c58dba2f14a37550ddc4`；开发分支：`feat/guided-planning-and-availability`。本轮针对实际使用反馈修订计划编辑，不重建工程，不改变云端数据格式。实现、单元测试、模拟器及真机证据分别报告；本契约不代表功能已验收。

## 需求与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| WIZ-01 | 一页填写一组相关内容 | 使用“事项 → 时间 → 重复与补充 → 确认”四步。事项收集名称、执行方式及可选分类；时间收集日期、时段与可用空档；重复与补充收集周期和按需展开内容；确认显示最终安排。每步不是只有一个孤立输入框。 |
| WIZ-02 | 随时记得已填内容 | 各步保留简明摘要和当前步骤。返回、切换步骤、展开详细内容、暂时关闭及校验失败均保留草稿；摘要允许返回相应步骤修改。已有草稿时再次添加或修改其他安排不得静默覆盖，须继续原草稿或明确放弃。最终确认前不保存模板、不写版本或执行记录。 |
| AVL-01 | 提前展示并限制占用时段 | 以设备本地分钟和半开区间 `[start,end)` 计算。已有“工作 08:00–12:00”时，08:00 至 11:59 不能作为冲突开始时间，12:00 可以衔接；有效结束时间只能位于所选连续空档。占用区显示计划名称和具体时间，可用区按时间顺序列出。 |
| AVL-02 | 明确冲突位置与调整方向 | 时间、日期或重复规则改变时立即重算。提示包含发生日期或星期、已占用事项名称和起止时间，并给出可选空档或下一合法起点。不得只显示“时间冲突”“目标冲突”。全天无空档或剩余时长不足时明确说明，不能给出不可保存的默认推荐。 |
| AVL-03 | 重复规则评估完整 | 每天、工作日、自选星期、生效起止、跳过日期和替换日期使用同一调度语义。不能只检查当前显示日或未来七天而漏掉较晚生效的冲突。时间页首次选择单日后，重复页改变周期必须重算；若旧时段不再可用，应阻止确认并允许修改时间或重复范围。已有重复计划首次进入时间页就有冲突时，重复设置仍须可达。 |
| EDIT-01 | 修改时排除自身并保留复杂数据 | 编辑当前时间块时排除其旧占用，其他规则及同组其他时间块仍是占用。多块、并行任务、顺序动作、可选说明、来源关联和已有标识不能因向导切换被压平或清空；确认摘要按时间排列。 |
| ID-01 | 用户不处理内部目标标识 | 正常新建和修改不要求用户修内部 ID。扩大重复范围等操作引发内部标识重合时，由服务层识别并处理可安全分离的计划标识；原历史快照和执行来源不能被重写。真实时间重叠仍需明确显示名称与时段，不能把 ID 问题伪装成时间问题。 |
| EXC-01 | 解释某一天的变更 | 单次安排不显示周期例外入口。重复计划按需提供“某天不执行”及“仅修改某天”，解释“其他日期照常”。操作前显示日期、作用的安排/时段数量及替换结果；多时段规则不能只写“特殊安排”就让用户误以为只改当前一项。 |
| HIST-01 | 历史及失败保护 | 维持只读日期锁检查与保存前复查。已执行或过去日期的原日快照不变；锁日单次拒写保留草稿，周期规则清楚说明未来生效。冲突、损坏数据或写入失败不产生伪成功；不会自动挪动、缩短或删除已有计划来制造空档。 |
| QA-WIZ-01 | 真正验证编辑场景 | 新增、修改、返回草稿、周期变化、无空档、衔接边界、排除自己/保留兄弟占用及例外均有纯逻辑/页面回归。核心向导在微信开发者工具真实编译、输入、选择、前后步和保存；390px/320px检查摘要、时间区与底部操作，原数据精确恢复。 |

“只能从12点开始”表示不能从已有08:00–12:00占用内部开始，并不禁止用户主动选择更早的合法空档。系统自动按开始时间展示及排序；自动建议或选中空档不代表已经保存，也不允许移动别人的安排。

## 模型及职责

- 保持 `TimeBlock`、`Task`、`Action`、`Record`、`Schedule`、`PlanTemplate` 与 `DailyInstance` 数据格式。向导步骤、摘要、候选分钟与冲突明细属于页面/分析状态，不混入用户执行记录或云同步 payload。
- 可用性分析为纯函数：输入已验证模板、草稿规则、正在编辑的块身份、日期与候选时段；输出有名称/时间/发生日上下文的占用、空档、合法候选及冲突。函数不读微信存储、不保存模板、不产生实例。
- 周期展开共用一套语义，服务、向导和验证不能各自实现不一致的“这一天是否执行”。有限例外与周期交集必须覆盖普通重复出现及例外见证日期，不能用任意七天窗口当作无冲突证明。
- 已有记录日期和已锁定快照日期属于保留事实，包括未来日期；服务将它们作为 `excludedDates` 传入可用分钟、整组冲突与导入预览分析。模板不会改变这些日的安排，不能用它们制造不可修复的模板冲突；跳过某次锁定的普通重复后，仍须寻找下一次未锁定的重复见证，不能漏检未来冲突。手工选择锁定日新建单次或修改该日例外仍拒绝。
- 时间选项仅提供合法候选；微信原生时间选择器不能表达任意禁用区间时，应使用可过滤候选的原生选择组件并配合占用/空档列表，不能让用户先选中忙时再等到保存时报错。分钟精度保留，结束边界可衔接，开始必须早于结束。
- 时间范围沿用当前模型的有效 `HH:mm` 范围；没有实现跨日/24:00 支持时，不得暗示可以跨午夜保存。
- 保存服务负责版本比较、冲突最终复查、标识安全处理、排序和历史固化。页面上的预检查不能代替保存时最终检查；模板在向导期间改变时不得覆盖更新后的内容。
- 现有模板即使有旧版允许的重叠也须能读取、展示并逐步修复。不能为了新增选择限制，把存量数据突然判为损坏而挡住整个计划页。新增/编辑与导入的策略要明确区分，并在导入预览阶段定位问题。
- 普通保存只检查本次编辑规则涉及的未来可变日期；新导入模板检查其中所有规则的未来可变日期，重叠在确认前按日期、计划名及起止时间拒绝。读取存量模板和恢复既有版本保留原有结构校验行为，不以新导入限制阻断历史读取。
- ID 重排仅限有明确编辑意图且能安全分离的计划对象；已锁定实例、记录、照片关联、延期来源及未编辑的计划不因技术碰撞而重写。需要维护引用的情形必须由服务实现并测试，不能由 WXML 或错误字符串替换掩盖。

## 用户文案与交互

冲突示例：“11月3日的10:00–11:00与‘工作’08:00–12:00重叠，可从12:00开始。”无空档示例：“这一天没有足够的连续空闲时间，可换一天或缩短本次时长。”所有选择同时保留文字说明，不只依赖灰色、红色或图标。

例外示例：“工作日09:00–12:00工作，11月4日不执行；其他工作日照常。”修改示例：“仅在11月4日将这组安排替换为预览中的2个时段；其他日期照常。”日期和预览须取实际草稿，不硬编码演示日期到产品文案。

步骤页保持当前中性底、白卡、蓝色行动点；主要操作至少44px，长名称、多个冲突和分钟选项可滚动。摘要应简短且可展开，不用固定大段说明挤压填写区域；底部前后步及保存操作不能遮挡内容或安全区。
