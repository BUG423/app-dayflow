## 可重复执行

先运行类型与单元检查，再由具备本机桌面权限的普通Windows宿主执行：

```powershell
npm run typecheck
npm test
pwsh -NoProfile -File scripts/wechat-local-backup.ps1 -Mode Validate -Label default
pwsh -NoProfile -File scripts/wechat-local-backup.ps1 -Mode Layout -Label narrow
```

`default`要求真实390px视口，`narrow`要求320px；标签不会切换模拟机型。`Validate`覆盖完整保护及故障恢复，`Layout`保留导出、文件预览、确认恢复/撤销与布局检查，不重复全部负例。两种模式都执行五页WXML/WXSS编译、源码冻结核对、文件清理及原数据双恢复。

脚本只使用合成计划、历史反馈、休息原因、照片和备份包。开始时精确备份全部`dayflow.*`键，包含恢复点等新增键；收尾通过一次官方刷新重建SDK上下文，再清理已证明归属的合成文件，并以分段检查点完成原始数据恢复、返回实际当天及第二次恢复与精确读回。该流程不再用跨evaluate函数对象身份比较声称原wx函数精确恢复。未完成授权任务不重放，不以新目录绕过未恢复运行。

## 断言与文件归属

- 真实页面点击导出后读取、校验合成JSON文件，记录包含项和数量；导出不改变业务存储，也不自动发送。只有独立发送按钮调用受控分享回调，真实收件人未打开。
- 正式备份和注入前只读检查原页面，遇未保存编辑器、阶段草稿、反馈/休息/延期表单、待确认备份或未完成原生动作时中止，不关闭草稿。原恢复点为writing/recovery-required、索引不合法、journal缺失/校验不符时也拒绝测试，先由用户完成正常恢复；只返回布尔状态，不输出页面内容。合法restored恢复点及其原有文件照常备份保护。
- 文件取消、损坏JSON、包内未结束执行、照片上下文不兼容均保留原值。有效备份先展示计划名、日期范围和记录数量；预览及最终取消零写，确认后恢复七组业务内容，照片关联保持，提醒关闭且不导入订阅配置。
- 正常撤销恢复原始值及键存在性；预览过期拒绝覆盖。单次写入失败精确回滚；写入和回滚同时受控失败时显示继续恢复原内容，移除故障后由真实按钮完成恢复。
- 当前进行中执行和暂停计时阻止恢复。结束计时必须经单独确认；取消不写，确认仅结束身份匹配的计时，不更改执行事实。同一备份可重新检查，但不会因此自动恢复。
- 合成选择文件和一像素照片只写入`USER_DATA_PATH`下的随机nonce目录，目录必须预先不存在，并以所有权标记和固定文件清单验证。导出与恢复journal由真实服务写到其正常备份目录；先记录已有文件名，仅将本轮新增、符合命名且包内计划id含本轮nonce的文件登记到私有manifest。
- 清理前重新核对路径、名称、字符数和校验和，只删除manifest精确指向的合成文件。旧备份不读取、不删除；未知文件、内容变化或无法证明归属时保留文件并标记待恢复。目录只能在白名单文件清理后确认空目录再移除，不执行递归删除。
- 文件清理失败仍尝试恢复原业务数据，保留待清理状态；若原始存储已经双恢复完成，后续恢复入口只处理剩余文件，不用旧快照再次覆盖用户新内容。

## SDK与恢复检查点

- 官方`simulator_refresh`调用前持久化`sdkRefreshRequested`，只请求一次上下文重建；之后仅有界只读检查`appReady`、`pageReady`、`harnessAbsent`与`apisReady`全部为true，再记录`sdkContextRestartVerified`。不重复刷新，也不声称跨evaluate的函数对象引用相同。
- 原值恢复分first、UI和second三段，各自保存started及verified检查点。已started但未verified的段在重连后仅比较当前全部`dayflow.*`原值及存在性；有差异即拒绝重放，不能用旧快照覆盖后续数据，也不重写原备份或旧hash基线让检查通过。
- `storageRestored`持久化后，后续入口只处理尚未清理的合成文件，不再重建SDK或重新套用旧快照。恢复和文件清理状态分别记录，不能把清理完成当作数据双恢复完成。

运行日志、前后原值、合成导出文件清单及含个人安排的原始界面仅留在忽略的本地`artifacts`。公开报告只记录实际结果和元数据。任何失败运行必须单独记录，不累计为后续通过断言。
