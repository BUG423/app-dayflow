日期：2026-10-31。本报告记录本轮实际日志，不把已有脚本、纯逻辑测试或上一轮结果视为本轮模拟器通过。

## 重复运行

冻结业务源并完成 `npm run typecheck`、`npm test` 后，由有本机桌面访问权限的普通 Windows PowerShell 运行：

```powershell
pwsh -NoProfile -File scripts/wechat-planning-wizard.ps1 -Mode Validate -Label default
pwsh -NoProfile -File scripts/wechat-planning-wizard.ps1 -Mode Layout -Label narrow
```

第一条要求模拟器实际宽度为390px，第二条要求320px；标签本身不会修改设备。每次都记录 `miniprogram` 源文件 SHA-256 清单并检查运行期间未修改业务源。脚本使用官方微信开发者工具 CLI，先检查登录与版本；仅在工具要求时读取进程内可选 CLI token，不读取凭证文件。原生多列选择器通过公开的组件 `columnchange/change` 事件选择实际候选，日期选择通过组件 `change` 事件设置。覆盖确认通过官方 `automation_wx_api` 给 `showModal` 提供明确标记的受控确认/取消响应，再由真实页面事件和保存服务执行；不使用 `callMethod` 代替按钮。这些证据不能替代手工操作原生确认弹窗、日期弹窗、滚动选择器或手机输入法验收。

## 本轮覆盖

- 简化四步：名称、合法日期与时间、直接点击重复选项、最终确认；更多设置默认收起，普通流程不出现新增日期例外入口。
- 外部08:00–12:00占用仍可选择，明确询问是否替换；取消不改变存储。12:00可衔接，真实空档与可确认替换的时间分开展示；同组兄弟时间块继续禁选，不能静默删除自身其他内容。
- 从周日08:00–12:00扩大为每天时，一次确认所有受影响工作日的完整旧09:00–12:00安排；更改重复范围会使旧确认失效。最后保存才提交一次新版本，周一至周五逐日检查旧上午块移除、下午与无关事项保留，历史快照与记录不变。生效前的旧模板片段可保留，不能据此误判未来仍冲突。
- 外部全天占用可选但必须明确确认删除完整00:00–23:59时间块；同组全天兄弟占用没有可选时间。60天后的占用仍列明事项和完整时间，不能只检查当前一周。
- 返回、临时关闭与继续填写不写模板；最终版本或日期锁变化拒绝写入且保留草稿。
- 复杂已有计划包含多个时段、Action、origin和预存日期调整；经过简化向导保存后完整保留，界面无需编辑例外。
- 今日休息：可选理由、取消不写入、确认后全部原定时间块显示暂停；已完成记录和历史不动，正在执行的事项追加真实中止事件，未执行事项不伪造跳过或完成。
- 独立倒计时暂停并保留剩余时间；恢复安排不会自动开始事项或倒计时；今日页面及详情页的完成入口在休息时拒绝执行。
- 非今日日期不继承今日休息控制；休息理由及休息事实仅保存在当前本机，不承诺云同步或撤回已经登记的云订阅消息。
- 390/320检查表单、重复按钮、摘要、底部操作、休息理由与恢复入口的实际矩形和截图，主要操作至少44px且不横向溢出。

## 数据恢复

只使用合成中文数据，无个人照片、病史、私密AppID或真实云操作。开始前备份全部 `dayflow.*` key，包括未知前缀key的存在性和值。结束或非挂起失败时，先恢复存储，重新打开实际今天，再恢复一次并精确读回；只有恢复通过才清除待恢复标记。原始日志、截图、备份和控制台仅留在被忽略的本地 `artifacts/wechat-planning-wizard`，不提交公开仓库。

覆盖确认 mock 在调用前记录恢复意图，场景完成后立即还原；最终恢复原界面前再次还原全部已记录API。遇到CLI `pending` 时记录原任务并停止，不重发点击或覆盖备份；先用原 `RunDirectory` 的 `-Mode Poll` 查询终态，再按需要 `-Mode Restore`。已恢复的旧目录拒绝重复恢复，防止覆盖更新的用户数据。
