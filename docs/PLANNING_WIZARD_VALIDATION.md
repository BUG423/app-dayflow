## 可重复入口

先执行 `npm run typecheck` 和 `npm test`，冻结 `miniprogram` 业务源，再由有本机桌面权限的普通 Windows PowerShell 执行：

```powershell
npm run test:wechat
pwsh -NoProfile -File scripts/wechat-planning-wizard.ps1 -Mode Layout -Label narrow
```

第一条要求模拟器实际宽度为 390px，第二条要求 320px。标签不会修改机型或假装改变窗口宽度；脚本从微信 API 读取真实宽度并校验。新 `test:wechat` 和旧 `wechat-iteration.ps1 -Mode Validate` 已转向独立向导验收。旧脚本、旧 Restore/Poll 入口和历史报告保留。

原生多列选择器的候选从页面实际 `range` 读取，使用官方 `automation_element_action` 的 `columnchange/change` 组件事件选择。页面按钮使用真实元素 `tap`、文本使用 `input`。这不等同于人手打开原生选择弹窗并滚动选项，不使用 `callMethod` 代替交互。

## 数据与恢复

- `wizard-acceptance-fixtures.js` 只生成合成中文计划、合成历史记录和快照；三个场景均经过当前真实模板、记录、快照校验器。没有用户照片、病史、云请求或私密配置变更。
- 开始前备份全部 `dayflow.*` key，包括未知前缀 key 的存在性和值；运行中只替换该前缀。Node 输出在脚本内部明确按 UTF-8 解码，中文不依赖调用者控制台编码。
- 每个场景通过 `reLaunch` 丢弃前一场景缓存草稿。结束和非挂起失败后，先恢复所有存储，再 `reLaunch` 今日页、选中实际当地今天，再恢复一次并精确读回。待恢复标记只有在两次恢复和原界面确认完成后清除。
- CLI 返回 pending 时只记录原任务 ID，不重放点击或恢复。待原任务终态后，使用同脚本 `-Mode Poll -RunDirectory <原路径>`，随后用 `-Mode Restore -RunDirectory <原路径>`。不要启动另一个验收覆盖备份。
- 日志、备份、截图、完整控制台快照和源码 SHA-256 清单只保留在被忽略的本地 `artifacts/wechat-planning-wizard`。验收前后源码清单必须一致。日志和备份不提交公开仓库。
