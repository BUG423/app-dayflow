# Dayflow · 日程流

以时间为入口、以行动为核心的微信原生小程序（TypeScript）。

## 已交付的基础版本

- 周一至周日自动定位当天；支持上一周、下一周与指定日期切换
- 今日时间轴：固定占用 / 并行任务 / 顺序训练
- 自动识别当前和下一时间块，支持折叠展开
- 吉他与声乐独立勾选；训练动作逐项打卡
- 本地保存完成状态，昨日复盘，周度完成情况
- 内置七日**示例**日程；工作时间和训练动作数据不代表医学建议

> 本地数据为默认路径。本轮按明确契约补充计划编辑、导入、执行状态、反馈、照片、统计、提醒和可选同步；具体实现与实际验证状态分别见下方文档。云同步默认关闭，阶段由用户自主选择，不强制解锁。

## 启动

1. 在 Windows 安装微信开发者工具和 Node.js。
2. 克隆仓库，在微信开发者工具中**导入项目**（选择仓库根目录，含 project.config.json）。
3. 在本机配置有权限的小程序 AppID；不要将本机配置、AppSecret、私钥或云端凭证提交进仓库。公开配置保留演示占位值。
4. 工具设置启用 TypeScript 编译插件；本项目 project.config.json 已配置 useCompilerPlugins。
5. 在项目根目录执行 npm ci、npm run typecheck、npm test。
6. 点击微信开发者工具「编译」，在模拟器内打开「今日」。

## 从测试号接入云服务

当前 `-601059` 表示测试号不支持云服务，不能通过“我的”页面开启一个开关解决。需要先注册正式微信小程序，在本机使用其 AppID，并确保登录微信具有开发权限；再从开发者工具的云开发入口使用对应微信公众平台账号进入，核对小程序与腾讯云账号/环境的关联关系。

更换 AppID 前应保留私有本机备份：不同 AppID 的缓存和文件沙箱可能不同。“复制当前模板”仅导出计划，不含执行记录或照片文件；旧数据迁移需要独立验收，不能承诺自动带过去。本轮未修改 AppID。

用户须自行完成登录、协议、授权及环境计费选择。环境可用后，再按 [云函数部署说明](cloudfunctions/README.md) 配置和部署同步、私有文件访问与单次提醒；先用两个测试账户验证隔离、冲突和权限，再验收订阅发送，不承诺永久免费或无限推送。完整步骤及官方来源见 [云接入边界](docs/UX_REVISION_CONTRACT.md#云服务接入边界)。不需要把 AppSecret、私钥或登录凭据发给开发者或提交到仓库。

## 工程目录

- miniprogram/pages：今日、计划、训练详情、统计、我的
- miniprogram/data：默认示例与兼容页面的叶子任务投影
- miniprogram/utils：日期与完成率的纯逻辑
- miniprogram/services：计划快照、执行记录、计时、统计、照片、提醒与可选同步
- tests：Node 内置测试框架单元测试
- docs：产品需求和架构约定

云函数使用客户端纯验证器的构建产物。修改日期、计划、记录、偏好、日实例或照片验证逻辑后运行 `npm run build:cloud-validation`，并提交对应共享产物；`npm test` 会只读检查源与产物一致性，不会自动改写生成文件。真实云部署和权限验收另按验证报告执行。

后台提醒的独立定时入口通过 `npm run build:reminder-tick` 构建共享业务模块，保持 manager 与 Tick 一致。默认不登记或发送后台任务；真实模板、权限、官方触发方式和微信票据均需按 [云函数说明](cloudfunctions/README.md) 核验，发送接口成功仅表示已提交微信。

## 隐私及安全

公开仓库仅包括泛化的计划示例，不包括个人医疗情况、用户记录、照片、凭证、AppSecret、云环境密钥。涉及动作强度的示例必须由使用者按实际情况咨询专业人员后使用；用户可跳过或停止任务。请勿把该模板宣传为康复处方。
